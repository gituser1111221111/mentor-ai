# Financial amounts and speech audit

Audited base: main `f6341ab` (includes playback and number-pronunciation fixes). Working branch: `fix/financial-speech-validation`. No merge, deployment or remote publication is part of this audit.

## Confirmed failures and fixes

| Confirmed reproduction before the fix | Cause | Fix and regression coverage |
|---|---|---|
| A stored answer containing unverified `$100,000` was sent to ElevenLabs, with `X-Amount-Check: unverified`. An existing test explicitly expected this behavior. | The final speech boundary warned but proceeded. | Recompute validation from the exact stored text and its retained calculations before normalization, cache lookup or synthesis. Refuse unverified text with 422; prove no provider request is made. Old records missing context fail closed. |
| `$420k`, `$420 million`, `-$420.00`, `$.45`, malformed `$4,20`, and written-out unsupported amounts passed when only positive `$420` was authorized. | Loose digit matching skipped suffixes/leading decimals, ignored signs and separators, and did not inspect number words. | Strict literal tokenization and separator/sign checks; conservative rejection of unsupported scales, notation and written-out quantities. Signed sub-dollar normalization preserves the minus sign. Tests cover each reproduced form. |
| `$420 per week` passed for a monthly amount; `12 years` passed for a 12-month result. Any integer, including a percentage, could authorize `timeToGoalMonths`. An annual APR could be described as a monthly rate. | Values were pooled without their period/type. | Explicit cadence/duration checks against the relevant calculation fields; separate APR cadence; payoff metadata requires an actual month quantity. Supported canonical amounts and periods remain accepted. |
| A number from one field could back an explicit different-field claim: savings `$1780` passed when savings were `$420` and lowest income was `$1780`. | Numeric membership did not bind even simple named snapshot claims to their field. | Bind explicit savings, total debt, essentials, lowest-month and average-month claims to their matching fields. Regression demonstrates both the rejected mismatch and accepted correct claim. This is limited field binding, not a full language-understanding verifier. |
| Conversational replies, general replies without a profile, and appended `needsInfo` questions could carry unchecked financial figures into display and then speech. | These model-output paths bypassed the main candidate/picker validation. | Check all these paths, use number-free clarification fallbacks where facts are absent, and omit unsupported numeric follow-up questions. Model-client regressions inject `$9999` into each path. |
| Dollar amounts from the user's latest message were added to the snapshot's allowed-value set. A new amount could be treated as calculated advice while using an older profile. | `userStatedAmounts` was labeled as input in prose, but the validator recursively admitted its contents. | Keep the metadata labeled, but exclude it and numeric names/source labels from calculation authority. New unsupported amounts and recognized corrected/personal financial statements prompt an input update rather than silently planning against old facts. No automatic financial parsing or new calculation engine was added. |
| An old request could finish after profile replacement or a newer question, write old history and restore stale speech eligibility. A portfolio/attachment change did not invalidate an old turn's meaning. An existing cached clip remained usable after those changes. | Asynchronous results and stored speech were not bound to current input/request context. Text hashes alone do not establish current financial facts. | Clone the input profile for generation, bind results/turns/speech receipts to a profile fingerprint, input revision and request sequence, reject stale completions with 409, and refuse stale repicks/comparisons/expansion. Recheck context before provider submission and after synthesis, including cache hits. Browser input updates stop speech/end active capture. Race tests cover profile replacement, newer questions, cached audio after attachment changes, updates while synthesis runs, and starting over during a profile-free general reply. |
| `$401k`, `$529 savings`, and `$1099` were rewritten as account/tax-form names instead of currency amounts. | Account-name replacements ran before currency conversion. | Convert currency first, retain ordinary `401(k)`/`529 plan` pronunciation, and bump the pronunciation version so old normalized audio is not reused. Existing models, voice ids and settings are unchanged. |
| Input `1,00` became 100 after stripping commas; APR `7.999` silently became 8.00%. A decimal duration could be relabeled as money by display formatting. | Permissive input cleanup, implicit APR rounding, and a formatter that guessed any decimal was dollars. | Validate grouping/precision before normalization and require correction of ambiguous inputs. Preserve explicit duration units in display formatting. Arithmetic and financial calculation formulas are unchanged. |

## End-to-end trace

1. Typed or transcribed text reaches `/api/chat`; structured inputs reach `/api/profile`, portfolio upload, or attachment endpoints. Structured money/APR inputs now reject ambiguous grouping or unsupported precision. Speech-to-text itself remains unverified input.
2. A new accepted chat request gets a request sequence and a cloned profile. The deterministic `calcLibrary`/existing finance functions compute cents, rates and timelines. User-message amounts and document prose are not calculation authority.
3. Classification and generation still use the existing progressive orchestration. Numeric statements in bypass paths are checked. Recognized corrected financial facts request updated inputs; they do not silently replace structured facts.
4. Candidate validation checks copied values and explicit units. The mentor still selects from the validated candidate set. Its text is checked as before, with the stricter shared validator. Personality/core data are untouched.
5. Display formatting preserves duration labels. Appended model questions cannot introduce unchecked amounts after picking.
6. Before storing/returning a result, the route confirms that input/request context is still current. Speech receipts retain the exact displayed text, calculations, text hash and context. A stale result cannot restore old session turns or overwrite newer history.
7. `/api/voice/speak` ignores browser-supplied text. It looks up a session-owned receipt, confirms its context, and recomputes numeric validation before serving a cache hit or sending text to ElevenLabs.
8. The deterministic number-to-words converter changes pronunciation only. Currency is handled before account names. Cache keys already include text, voice, model/settings and pronunciation version; this fix advances that version. Context is checked again around asynchronous synthesis.
9. Browser playback retains the single-owner cancellation behavior. Financial-input updates also invalidate pending autoplay and end active voice capture. The existing interruption and hands-free completion browser assertions remain in place.

## Verification

- Full `npm test`: 106 passed, 0 failed, including existing calculation reconciliation, progressive generation, financial validation, voice lifecycle and pronunciation tests plus new audit regressions.
- `npm run db:test`: 20 local PGlite checks passed. Hosted Supabase services were not exercised.
- Chromium browser suite: 15 coaching requests plus short/long fixtures completed; typed interruption, hands-free completion, exact normalized speech payload comparison, zero decoding errors and zero mid-playback waiting events. Fixtures were updated to provide valid calculation/context receipts rather than bypassing the new admission checks.
- `git diff --check`: clean. `lib/finance.js`, persona/core files, catalog identities and `lib/voice.js` are unchanged.

Some old test expectations were deliberately corrected: unverified speech must be refused, user-provided numbers must not become calculated authority, and scripted option-generation fixtures must paraphrase numeric teachings when their numbers are not backed by attached calculations. The actual mentor teachings and option bank were not edited.

## Remaining risks and behavior changes

- Numeric backing plus explicit field/unit checks cannot prove arbitrary financial reasoning. The checker does not establish the correct premise, suitability, or source relevance for every possible paraphrase. It is intentionally conservative about unsupported notation and number words and can reject a legitimate reformulation.
- This engine has no authoritative current tax-limit, market-return or regulatory-rate feed. Those facts must not be presented as verified from arbitrary model knowledge. No live financial-source accuracy claim is made by these tests.
- Financial changes stated in ordinary conversation are not a complete structured-profile update mechanism. Recognized new/corrected figures ask the user to update inputs; less explicit changes still require confirmation. The application cannot infer every spoken or written update correctly.
- Historical answers remain visible, but old speech receipts become unavailable after a newer question or changed financial context. Legacy receipts/turns without audit context require a fresh answer. This is intentional stale-data rejection.
- The server refuses stale results before delivery, but cannot retract audio already delivered to a different browser/device. Same-tab interruptions and financial-input updates stop playback; there is no cross-device push invalidation service.
- Speech recognition may transcribe a real amount incorrectly, and the final voice may pronounce a correctly normalized phrase incorrectly. No real ElevenLabs/model credentials were available for acoustic or live-model evaluation. Tests use model/provider stand-ins and a synthetic MP3, not a claim of real-world pronunciation accuracy.
- Existing prototype anonymous-session persistence, restart and multi-instance limitations remain. This is an accuracy audit, not a production compliance certification.
